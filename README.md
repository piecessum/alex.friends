# friends

Личное пространство Алексея Масюты — заметки и лонгриды про UX, коллекция пластинок и вишлист. Сайт-компаньон к [сайту-резюме](../alex).

**Стек:** Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Framer Motion · next-themes. Тот же дизайн-фундамент, что и у резюме.

## Локально

```bash
npm install
npm run dev   # http://localhost:3000
npm run build # production-сборка
```

## Деплой

Push в `main` → автодеплой на Vercel.

После деплоя пропиши реальный адрес сайта-резюме в `lib/site.ts` (константа `RESUME_URL`) или через переменную окружения `NEXT_PUBLIC_RESUME_URL` в настройках Vercel.

## Утренняя газета без отдельной оплаты API

Автор запускается на GitHub Actions через Codex CLI с отдельным входом в
ChatGPT. Mac может быть выключен. Расходуются лимиты существующей подписки;
платного OpenAI API и платного запасного провайдера обложек нет.
Секрет `OPENAI_API_KEY` этой цепочке не нужен.

Будильник — Cloudflare Worker `alex-friends-research-clock` с Cron Trigger
каждую минуту. В 18:00 и 22:00 МСК он запрашивает подготовку следующего
выпуска через защищённый `/api/research/tick`. Запрос создаёт маркер в
`.openai/research-ticks/`, и обычный push запускает автора без ожидания cron
GitHub. Автор → проверка сборки → обложки → вечерний деплой. Расписание
GitHub оставлено только как резервное; его запуски могут сильно опаздывать.

Пн–пт в 08:00 МСК — статья, суббота в 08:00 — дайджест, воскресенье — выходной.
Подготовленные страницы динамические: до 08:00 скрыты, с 08:00 доступны
без повторного деплоя. Утренний Worker отправляет готовый выпуск в Telegram;
до конца 09-го часа повторяет проверку. Для подготовленного выпуска это
быстрая отправка, без генерации и сборки утром. Если выпуск отсутствует,
запрашивается облачное восстановление. Статья/дайджест за день не дублируются.

Отдельный случайный `RESEARCH_CRON_SECRET` хранится в Vercel, GitHub и секрете
Worker. Он разрешает только операции газеты. Личные cookies администратора
не используются. Доставка из Worker и резервного GitHub job проходит через
общую атомарную запись в `.openai/research-delivery/`: два параллельных
издателя не отправляют два поста. Подтверждённый отказ Telegram допускает
повтор; неоднозначный сетевой результат требует сверки, чтобы не дублировать
уже принятый Telegram пост.

Установка/обновление будильника: Actions → Research author → `deploy_clock=true`.
Этот режим ждёт реального Cron Trigger, который записывает подтверждение
в `.openai/research-clock/<run-id>.json`. Первый час после установки Worker
дополнительно проверяет связь с сайтом; авторизации в подтверждении нет.
Изменения cron в Cloudflare могут распространяться до 15 минут.

Для первого подключения нужен отдельный вход ChatGPT для облачного робота.
Его `auth.json` передаётся прямо в секрет GitHub `RESEARCH_CODEX_AUTH`, без
вывода в чат или журнал. Вход редактора Zed для этого не используется.
Обновлённая авторизация сохраняется между запусками только в шифрованном
кэше AES-256-GCM; ключ выводится из исходного секрета. Открытый файл хранится
только во временной папке runner и удаляется в конце. Секреты GitHub и API
не передаются процессу автора. Шифрование проверяется тестами.

Если авторизация отозвана, подписка исчерпана или кэш обновлённого входа
удалён GitHub, может понадобиться повторное подключение робота. Проверка:
Actions → Research author → Run workflow → `check_only=true` — короткий
запрос через подписку без создания статьи. После подключения следует
проверить два запуска подряд, включая восстановление шифрованного кэша.

Локальный режим оставлен для ручной работы, но расписание на Mac отключено:

```bash
npm run research:setup                 # CLI в локальном .cache, не глобально
.cache/codex-cli/node_modules/.bin/codex login  # только если входа ещё нет
npm run research:local                # черновик, без публикации
npm run research:local -- --publish    # проверить сборку и отправить выпуск
```

Автор читает источники через веб-поиск, возвращает JSON в режиме только
чтения; скрипт проверяет результат и собирает сайт в отдельном git worktree.
Рабочие файлы редактора не меняются. Коммитится только новый материал,
обложки и Telegram обрабатывает прежний GitHub Actions workflow.
Проверка формы и доступности источника не заменяет проверку фактов человеком.
Отклонённый результат исправляется до трёх попыток с текстом ошибки.
DOI и разные ссылки arXiv распознаются как один источник. При сбое создаётся
GitHub issue, диагностика сохраняется отдельным артефактом на 7 дней (без
авторизации). Ручное восстановление: `issue_day=YYYY-MM-DD` в Research author
или `npm run research:local -- --publish --date=YYYY-MM-DD`.

Черновики и журналы: `.cache/research-draft-YYYY-MM-DD.json`,
`.cache/research-events-YYYY-MM-DD-<attempt>.jsonl`.
Проверки: `npm run research:test`, `npm run research:local -- --check`.

## Структура проекта

- `app/` — App Router: главная (`page.tsx`), `notes/` (заметки), `vinyl/` (пластинки)
- `components/` — `site-header`, `site-footer` (перелинковка с резюме), тема
- `lib/site.ts` — внешние ссылки и перелинковка
- `lib/utils.ts` — `cn()` helper
